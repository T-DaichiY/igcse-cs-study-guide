4.1 System Software and Operating Systems

What runs a computer behind the scenes, and how it juggles many jobs at once

Software comes in two kinds. System software looks after the computer itself. Application software is what you actually use to get a task done.

🍎 In plain words

Think of a restaurant. System software is the kitchen, cleaning staff and electricity — things the restaurant needs to even open. Application software is the menu — what the customer (the user) actually orders and uses.

🦠
Anti-virus
Checks files against known viruses and watches for suspicious behaviour
🧩
Defragmenter
Tidies up scattered file pieces on a hard disk so it runs faster
💾
Back-up software
Automatically copies your files somewhere safe
🖨️
Device driver
Lets a printer, mouse or other gadget "talk" to the computer

The operating system — the computer's manager

The operating system (OS) — like Windows or Mac OS — is the big program that runs everything else. It does nine jobs, but here are the important ones to know:

JobIn simple terms
InterfaceLets you talk to the computer (typing commands, or clicking icons)
Memory managementShares out memory so programs don't clash with each other
SecurityKeeps your account and data safe with passwords
Managing devicesTalks to printers, mice, etc. through drivers
File managementLets you create, open, delete and rename files
MultitaskingMakes several programs seem to run "at once"
🍎 In plain words

Multitasking is like a chef cooking three dishes at once — really, they're just switching quickly between pans. The computer's single processor does the same thing, switching between programs so fast it feels simultaneous.

Command line vs clicking icons

A command line interface means typing instructions. A graphical user interface (GUI) means clicking icons with a mouse, or tapping a touch screen. Most people use a GUI; programmers sometimes use the command line for extra control.

Starting up a computer

An application can't just run by itself — it needs the OS, and the OS needs a program called firmware to get everything going first.

🍎 In plain words

It's like a relay race: hardware gets switched on → firmware (the BIOS) wakes it up and finds the operating system → the OS loads → your app finally runs on top of all of that.

🧮 Starting up, step by step
1You press the power button.
2The BIOS (firmware) checks the hardware and finds where the OS is stored.
3A small program loads the OS into memory.
4Now apps like your browser or games can run.
➜ hardware → firmware → operating system → application

Interrupts — "excuse me, computer!"

An interrupt is a signal that tells the processor "stop what you're doing — I need attention now."

🍎 In plain words

Imagine you're reading a book and someone knocks on the door. You put your finger in the page (save your place), answer the door (deal with the interrupt), then go back to reading exactly where you left off.

⌨️
Hardware interrupt
Pressing a key, moving the mouse, a printer jamming
💻
Software interrupt
Trying to divide a number by zero, or a program error
⚠️ Just saying "mouse" or "keyboard" isn't enough — you need to say what happened on it, like "a key being pressed".

A buffer is a small waiting area in memory. It lets a fast computer and a slow device (like a printer) work together without the computer just sitting there waiting.

4.2 Languages and Translators

How the code you write becomes something the computer can actually run

Computers only understand machine code — plain 0s and 1s. Programmers usually don't write in that directly, so their code needs to be translated first.

High-level vs low-level languages

🍎 In plain words

A high-level language (like Python) reads almost like English — easy for humans, but it needs translating before the computer can run it. A low-level language (like assembly language) is written much closer to what the computer's hardware actually understands — harder for humans to read, but it can control the hardware directly and run very fast.

High-level languageLow-level language
Easy to read and writeHard to read — uses short codes (mnemonics) or raw numbers
Works on different types of computerTied to one specific type of computer/hardware
Quicker to write and fixCan control hardware directly, and runs fast

Assembly language

Assembly language uses mnemonics — short codes like LDA (load), ADD, and STO (store) — instead of writing raw binary numbers. An assembler turns it into machine code.

🍎 In plain words

LDA First, ADD Second, STO Sum is just a very low-level way of saying "add two numbers together" — the same idea as Sum = First + Second, just spelled out in tiny hardware-level steps.

Compilers and interpreters

Both turn high-level code into machine code — but in different ways.

CompilerInterpreter
Translates the whole program first, then it can runTranslates and runs the code one line at a time
Makes a finished file you can run any time, without needing the compiler againNeeds to be there every single time the program runs
Shows you all the errors at once, in one reportStops at the very first error it finds
Best for the finished programBest while you're still writing and testing
🍎 In plain words

A compiler is like translating a whole book into another language before handing it over. An interpreter is like a live translator at a meeting — translating sentence by sentence, on the spot, stopping the moment something doesn't make sense.

IDEs — a programmer's toolkit

An IDE (Integrated Development Environment) is a program that bundles together everything a programmer needs to write and test code — e.g. PyCharm, Visual Studio.

✍️
Code editor
A place to type and change your code
🔎
Error diagnostics
Spots likely mistakes as you type, before you even run the program
⌨️
Auto-completion
Suggests the rest of a word as you start typing it
🎨
Prettyprint
Colours the code so it's easier to read
⚠️ Don't just say "auto-completion completes the code" — that's just repeating the name! Explain how it works: as you start typing a word, the IDE offers to finish it for you.

🔑 Key words

System software
Software the computer itself needs to work.
Application software
Software you use to do a specific task.
Operating system
The manager program that runs everything else.
Firmware / BIOS
The program that starts the computer up and finds the OS.
Interrupt
A signal telling the processor to stop and deal with something.
Buffer
A waiting area in memory between a fast and a slow part.
High-level language
Easy-to-read code, e.g. Python.
Low-level language
Code close to the hardware, e.g. assembly.
Mnemonic
A short code like LDA or ADD.
Compiler / Interpreter
Translates all-at-once / translates line by line.
IDE
A toolkit for writing and testing programs.
