5.1 The Internet and the Web

Internet vs WWW, URLs, HTTP/HTTPS, browsers, DNS lookup and cookies

The internet vs. the World Wide Web

The word internet comes from INTERconnected NETwork — a worldwide collection of interconnected networks and devices. It is more of a concept than something tangible, relying on physical infrastructure to connect devices around the world. The internet uses transmission control protocol (TCP) and internet protocol (IP) to move data, and supports many services beyond web browsing — email, and text/audio/video chat.

The World Wide Web (WWW) is only part of the internet — the part accessed with web browser software. It is a massive collection of multimedia web pages, based on the hypertext transfer protocol (http/https), located using uniform resource locators (URLs). So the internet is the infrastructure, and the web is a service that runs on top of it.

InternetWorld Wide Web (WWW)
A worldwide collection of interconnected networks and devicesA collection of multimedia web pages and other information on websites
Makes use of TCP and IPUses http(s) protocols, written using HTML
Users can send and receive emailsURLs are used to specify the location of web pages
Allows online chatting (text, audio, video)Web resources are accessed by web browsers
The physical/logical infrastructure underneathUses the internet to access information from web servers
💡 Exam wording that scores marks: internet = "the infrastructure"; World Wide Web = "the collection of web pages" (accessed using the internet). Never treat the two terms as interchangeable in a technical answer — examiners specifically test that you know they are not the same thing.

Uniform resource locators (URLs)

A URL is a text-based address for a web page, typed into a browser's address bar. It follows the standard format protocol://website address/path/file name.

URL partWhat it contains
ProtocolUsually http or https
Domain hostwww
Domain nameThe website's name, e.g. hoddereducation
Domain type (+ country code)e.g. .com, .org, .gov (optionally .uk, .de)
Path / file nameThe web page or item requested; if omitted, defaults to the root directory
🧮 Example — breaking down a URL
1Take https://www.hoddereducation.co.uk/ict.
2Protocol: https. Domain host: www. Domain name: hoddereducation.
3Domain type + country code: .co.uk. Path/file name: ict.
➜ Always use the three category names: protocol, domain name, file name — not "www" or ".com" alone as a full "part."
⚠️ A URL must always be defined as a "text-based address for a website/web page" — not just "a website link," which is too vague to be credited in the exam.

HTTP and HTTPS

Hypertext transfer protocol (http) is a set of rules obeyed when transferring web files across the internet, defining how a browser requests pages and how a web server responds. When security (SSL/TLS) protects the data being transferred, the protocol becomes https — the "s" stands for secure. A green padlock symbol in the address bar confirms an https connection is encrypted.

FeatureHTTPHTTPS
SecurityNo encryption appliedData encrypted (e.g. SSL/TLS)
Visual indicatorNo padlock symbolGreen padlock symbol shown
Typical useGeneral, non-sensitive browsingBanking, shopping, login pages
📌 HTTPS is not a separate protocol — it is http with an added security layer. Never confuse http/https (a protocol for transferring pages) with HTML (the mark-up language used to structure the content of those pages) — this pairing is frequently tested.

Web browsers

A web browser is software that lets a user access and display web pages, by interpreting (rendering) HTML sent from websites — this rendering is the browser's main purpose. Beyond that, browsers share a set of separately creditable functions:

⭐
Bookmarks/favourites
Stores favourite pages for quick access later
🕓
User history
Keeps a record of websites visited
🗂️
Multiple tabs
Allows many pages open at once
◀️
Navigation tools
Move forwards/backwards through opened pages
🍪
Cookies
Stores cookies to remember user/site data
🔗
Address bar
Where a URL is typed to navigate
💡 Once "displays web pages by rendering HTML" has answered a question's purpose part, do not repeat it when asked for other functions — the mark scheme treats it as already used. Draw remaining answers from the list above.

Retrieval and location of web pages — DNS lookup

All websites are written in HTML and hosted on a web server that has its own IP address. The Domain Name Server (DNS) is a system that finds the IP address matching the domain name in a URL, so users never need to memorise IP addresses.

StepWhat happens
1The browser asks a DNS server for the IP address of the URL typed in
2If that DNS server cannot find it, the request is passed on to another DNS server
3The IP address is found and sent back; the first DNS server caches the URL/IP pair
4The IP address is returned to the user's computer
5The computer contacts the web server directly (using the IP address) and requests the page; the web server sends back HTML files
6The browser renders the HTML and displays the page
⚠️ Real June 2025 examiner evidence: in Paper 0478/12 Q5(c)(i), "some candidates found this question challenging... some candidates lacked the level of technical understanding required." Most only picked up marks for the DNS→computer and web server→computer steps, losing marks on the DNS lookup/re-routing detail and the outbound request steps. Name every component precisely — web browser, DNS, web server, IP address, URL, HTML — and always include the fallback step ("if the first DNS server can't find it, it is sent to another DNS server").

Cookies

Cookies are small text files sent by a web server to a browser, storing (key, data) pairs such as (language, English). There are two types:

FeatureSession cookiePersistent (permanent) cookie
Storage locationTemporary memoryHard drive
LifespanLost when the browser/session closesRemains until expiry or user deletion
Typical useKeeping items in a shopping basket during one visitRemembering login details between visits
💡 Uses of cookies: saving personal details, tracking user preferences, holding items in an online shopping cart, storing login details. A cookie is a small text file — not an image or executable, a common wrong-word trap. Many countries require persistent cookies to deactivate after six months, even before their expiry date.
📌 June 2025 examiner report: "Some candidates referred to it being used to store items in a shopping cart. This response could not be awarded as this was already given in the question." Never repeat a use already stated in the question stem when asked for "other" functions — the same rule that applies to browser functions applies here.

5.2 Digital Currency

Digital vs. fiat currency, cryptocurrency, and how blockchain resists tampering

Digital currency vs. fiat currency

Digital currency exists purely in digital format — it has no physical form, unlike conventional fiat currency ($, £, €, ¥), which is backed by governments and banks. Digital currency is an accepted form of payment; it can be transferred between accounts (e.g. PayPal, Apple Pay) because it only exists as data on a computer system, though it can be converted into physical cash if needed.

💡 Exam wording that scores marks: lead with "exists only electronically / has no physical form" as the defining feature — this is the specific fact the mark scheme rewards, not a vague "it's different because it's online."

Centralised digital currency vs. decentralised cryptocurrency

Traditional digital currency relies on a central banking system — a transaction between two people using different banks is routed through both banks and a central bank, which raises confidentiality/security concerns. Cryptocurrency overcomes this through decentralisation: transactions move directly between wallets, secured by cryptography and a blockchain network, with no central authority.

FeatureTraditional digital currencyCryptocurrency
ControlCentral banks and governmentsNo state control — rules set by the community
StructureCentralisedDecentralised (peer-to-peer)
Transaction visibilityNot publicly availablePublicly available and trackable
Security mechanismCentral bank's own securityCryptography + blockchain
⚠️ Don't confuse "digital currency" (the general category) with "cryptocurrency" (a specific, decentralised type of digital currency that uses blockchain) — a question may ask about one specifically, and conflating them loses marks.

Blockchain — a tamper-resistant digital ledger

Blockchain is a decentralised database: all transactions of networked members are stored across many interconnected computers with no central server. Whenever a new transaction happens, every networked computer gets a copy, so it cannot be changed without the consent of the whole network. Each new block contains three parts:

📄
Data
Transaction details — sender, recipient, amount
🔑
Hash value
A unique "fingerprint" (e.g. SHA-256) plus a timestamp
⛓️
Previous hash value
Points back to the block before it, linking the chain
🧮 Worked example — why changing one block breaks the chain
1Block 1 is the genesis block — it points to no previous block.
2Suppose a hacker alters the transaction amount stored in block 2. This changes block 2's hash value.
3Block 3's stored "previous hash" no longer matches block 2's new hash — block 3, and every block after it, becomes invalid.
➜ The tampering is immediately detectable, because the chain has been broken.
📌 A fast computer could try to quickly rebuild a whole new valid chain to hide tampering — this is prevented by proof-of-work, which forces a fixed delay (~10 minutes) before a block can be added, policed by miners who earn a commission for verifying blocks. Explaining "how blockchain protects against hackers" needs the full causal chain: change data → change hash → break link to next block → tampering detected → proof-of-work stops a fast rebuild. Simply asserting "it's secure" earns no marks.

5.3 Cyber Security

Threats — brute-force, malware, phishing, pharming, DDoS, social engineering — and their defences

Common cyber security threats

🔓
Brute-force attack
Systematic trial and error of password combinations; sped up by checking common passwords first, then a word list
📡
Data interception
Tapping a wired link (packet sniffing) or Wi-Fi signal (wardriving) to steal data in transit
🌊
DDoS attack
A botnet of infected computers floods a web server with requests until it crashes
🕵️
Hacking
Gaining illegal access to a system without permission; ethical hacking is authorised by the company itself
🎣
Phishing
Legitimate-looking emails trick the user into clicking a link or replying — the user must take an action
🚜
Pharming
Malicious code redirects the browser to a fake site automatically — no user action needed
🎭
Social engineering
Manipulating people (via fear, curiosity or trust) into breaking normal security procedures
🦠
Malware
Virus, worm, Trojan horse, spyware, adware, ransomware — see table below
Malware typeProcess and aim
VirusReplicates itself; needs an active host program to run (e.g. an infected email attachment)
WormStand-alone, self-replicating; spreads across a network with no host program or end-user action needed
Trojan horseDisguised as legitimate software; must be executed by the end-user; often installs spyware/ransomware
SpywareMonitors user activity (e.g. key-logging) and sends data back to the cybercriminal
AdwareFloods the user with unwanted advertising; not always harmful but hard to remove
RansomwareEncrypts the user's data and demands a ransom for the decryption key
🧮 Worked example — the process of a DDoS attack
1An attacker sends malware to a large number of computers.
2Malware turns each infected computer into a "bot," together forming a "botnet."
3The attacker initiates the attack — all bots send requests to a target web server at once.
➜ The web server cannot handle the volume of simultaneous requests and crashes.
⚠️ Phishing vs. pharming — the fact examiners test most: phishing needs the user to take an action (click a link, reply); pharming needs no user action at all — redirection happens automatically via infected code or DNS cache poisoning. If a question describes a user redirected without clicking anything, that's pharming, not phishing.

Keeping data safe — defences and countermeasures

ThreatMain countermeasures
Brute-force attackStrong/complex passwords, login attempt limits, two-step verification, biometrics
Data interceptionEncryption, SSL, avoiding public Wi-Fi, firewall on wireless routers
DDoS attackFirewalls, proxy servers, up-to-date malware checkers
HackingFirewalls, strong/frequently-changed passwords, intrusion-detection software
Malware (all types)Up-to-date anti-malware software, automatic software updates
Phishing / pharmingChecking spelling/tone/URLs, checking for https/padlock, up-to-date browser and firewall
Social engineeringSecurity awareness training, verifying identity before acting on requests

Authentication

Authentication proves who a user is, using one or more of three factors: something you know (password/PIN), something you have (a phone/tablet), or something you are (biometrics).

MethodHow it works
Fingerprint scanCompares ridge/valley patterns; very hard to replicate, but relatively expensive
Retina scanScans blood-vessel patterns using infrared light; very high accuracy but slow and intrusive
Face recognitionNon-intrusive, inexpensive, but affected by lighting or ageing
Voice recognitionFast and cheap, but low accuracy — disrupted by illness or recordings
Two-step verificationStep 1: username/password ("something you know"); Step 2: a one-time code sent to a registered device ("something you have")

SSL — how a secure connection is established

Secure Sockets Layer (SSL) is a security protocol used to encrypt data sent over a network. A user knows SSL is applied when they see https or a padlock symbol.

🧮 Worked example — the SSL handshake
1The browser sends a message to connect with the SSL-secured website, and asks the web server to identify itself.
2The web server responds by sending its digital certificate.
3The browser authenticates this certificate.
➜ If authenticated, the browser confirms this to the server, and SSL-encrypted two-way data transfer begins.
📌 Real June 2025 examiner evidence (Paper 0478/12, Q5(c)(ii), 6 marks): "Candidates found this question challenging. The most common marks awarded were for referring to the data being encrypted and referring to digital certificates being used in the process." Give the full four-step handshake in order — browser asks server to identify itself → server sends its digital certificate → browser authenticates the certificate → encrypted transmission begins if valid — rather than only saying "SSL encrypts data," which is where most candidates stopped.
💡 A proxy server sits between a user and a web server: it can hide the user's IP address, cache pages, and take the hit if an attack is launched (protecting the real web server) — a function the June 2025 report confirms candidates often fail to distinguish from a plain firewall. A firewall filters traffic in/out of a network but cannot stop a user bypassing it with their own hardware, employee carelessness, or a user simply disabling it.

📌 Exam tips

Real June 2025 evidence (Paper 0478/12, Q5c): DNS/web-server diagram questions and the SSL handshake explanation are where candidates "lacked the level of technical understanding required" — name every component (browser, DNS, web server, digital certificate) and every step in both directions, not just the final delivery step.

When asked for "other functions" (of a browser, or uses of a cookie), never repeat something already given in the question stem — it will not be credited again.
