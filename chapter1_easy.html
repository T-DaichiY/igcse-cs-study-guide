1.1 Number systems

How computers count, add, shift and store negative numbers using only 0s and 1s

A computer is really just millions of tiny switches. Each switch is either ON or OFF — nothing in between. So computers use binary (just 0s and 1s) instead of our normal counting system (denary, 0–9).

🍎 In plain words

Think of a row of light switches. Each one is either off (0) or on (1). A binary number just describes which switches are on.

Reading binary numbers

Each position in a binary number is worth double the one before it: 128, 64, 32, 16, 8, 4, 2, 1. To turn binary into denary, just add up the columns where there's a 1.

🧮 Converting 142 into binary
1Divide 142 by 2 repeatedly, writing down the remainder each time: 142÷2=71 r0, 71÷2=35 r1, 35÷2=17 r1.
2Keep going: 17÷2=8 r1, 8÷2=4 r0, 4÷2=2 r0, 2÷2=1 r0, 1÷2=0 r1.
3Read the remainders from bottom to top.
➜ 142 = 1 0 0 0 1 1 1 0

Hexadecimal — a shortcut for binary

Hexadecimal (hex) counts 0–9 then A–F (A=10 up to F=15). Every hex digit stands for exactly 4 binary bits, so hex is a short, easy-to-read way of writing long binary numbers — much easier for people to copy without mistakes.

🍎 In plain words

Writing out a long binary number like 1000011111110 1 is easy to get wrong. Its hex shorthand 21FD is about a quarter the length and much easier to read correctly.

Adding binary numbers, and overflow

Adding works just like normal column addition, carrying when a column adds to more than 1.

⚠️ An 8-bit "box" can only hold values from 0 to 255. If you add two positive numbers and the true answer is bigger than 255, the extra bit doesn't fit and gets thrown away — this is called overflow, and the answer that's left behind is wrong (too small).

Logical shifts — sliding the bits along

A logical shift slides every bit one or more places left or right. Shifting left multiplies the number by 2; shifting right divides it by 2. The empty space left behind is always filled with a 0 — a bit that falls off the end is lost for good.

🍎 In plain words

Imagine a line of people holding number cards. Shifting left means everyone takes one step left; whoever falls off the front edge is gone, and a new person holding "0" joins at the back.

Storing negative numbers — two's complement

To store a negative number, computers use a trick called two's complement: flip every bit (0↔1), then add 1. The first bit is now worth −128 instead of +128, which is how the computer knows the number is negative.

🧮 Turning +79 into −79
1+79 = 0 1 0 0 1 1 1 1.
2Flip every digit: 1 0 1 1 0 0 0 0.
3Add 1 to the end: 1 0 1 1 0 0 0 1.
➜ −79 = 1 0 1 1 0 0 0 1
⚠️ A common mistake: working out the number correctly but forgetting to make the final answer negative. Always check the first bit is 1 whenever the original number was negative.

1.2 Text, sound and pictures

How letters, sound and images get turned into 0s and 1s

Storing text — ASCII and Unicode

Every character on a keyboard needs a number the computer can store. ASCII gives every English letter, digit and symbol a 7-bit code (0–127). Unicode does the same job but for every language in the world (plus emojis), using up to 4 bytes per character. Unicode's first 128 codes are identical to ASCII.

🍎 In plain words

ASCII is like a phone book that only has English names. Unicode is a phone book big enough for every name in every country — but it keeps the exact same first page as the English one.

Sound files — turning sound waves into numbers

Sound is a wave (of air pressure) — it's analogue, not digital. A computer measures ("samples") the wave many times per second and stores each measurement as a binary number.

⏱️
Sample rate
How many measurements are taken each second (in Hz)
📏
Sample resolution
How many bits are used to store each measurement — more bits = more accurate
🍎 In plain words

Imagine tracing a wavy line by marking dots on it at fixed time gaps, then joining the dots. More dots per second (sample rate) and more precise dot positions (sample resolution) give a truer copy of the original wave — but also a bigger file. Don't mix up "sample rate" (Hz, dots per second) with "sample resolution" (bits per dot) — they're two different things!

Tracing dots along a wavy line
Each dot is one sample — a measurement of the wave's height, taken at a regular time gap, then stored as a number.

Bitmap images — a grid of pixels

🍎 In plain words

A bitmap image is like a mosaic made of tiny coloured tiles (pixels). Zoom in far enough on any digital photo and you'll see the individual squares.

🎨
Colour depth
How many bits describe the colour of one pixel. More bits = more possible colours.
🖼️
Resolution
How many pixels make up the whole picture — fewer pixels can look blurry ("pixelated").
Zoom in on any photo and you see the pixels
Every little square (pixel) has its own colour, stored as a binary number.

1.3 Storing and squeezing files

Measuring storage, working out file size, and compression

Measuring data storage

A bit is one 0 or 1. A nibble is 4 bits. A byte is 8 bits (2 nibbles). Bigger amounts are measured in kibibytes (KiB), mebibytes (MiB), gibibytes (GiB) and so on — and each one is exactly 1024 times the one before it, not 1000.

🍎 In plain words

Computers count in powers of 2, so storage sizes jump in steps of 1024, not the neat 1000 we're used to from kilograms or kilometres. Always multiply/divide by 1024 for these units.

Working out a file's size

Rule for images: file size (bits) = resolution (pixels) × colour depth (bits). Rule for sound: file size (bits) = sample rate × sample resolution × seconds (× 2 for stereo).

🧮 Working out a sound file's size

A 10-second, mono (1 channel) recording at 8000 Hz, 16-bit resolution.

18000 × 16 = 128 000 bits per second.
2× 10 seconds = 1 280 000 bits, ÷ 8 = 160 000 bytes.
➜ 160 000 bytes (about 156 KiB)

Why do we compress files?

Big files are slow to send and take up lots of space, so we compress them — this saves storage space, uses less bandwidth, and makes files quicker to upload, download or stream.

🔓
Lossless
You get the exact original file back when you decompress it. Nothing is lost.
🔒
Lossy
Some data is thrown away for good, to make the file much smaller (e.g. MP3, JPEG).

Run-length encoding (RLE) — a lossless trick

RLE spots runs of the same value repeated and stores just "how many, and what" instead of writing the value out every time.

🧮 RLE on "aaaaabbbbccddddd"
1Original: 17 characters = 17 bytes.
2Count each run: 5 a's, 4 b's, 2 c's, 5 d's.
3Store as 4 pairs of (count, character) = 8 bytes.
➜ 17 bytes → 8 bytes (under half the size!)
⚠️ RLE only helps when there are long runs of the same thing. A string like "cdcdcdcdcd" (no repeats) barely compresses at all — sometimes it can even get bigger!
🍎 In plain words

Instead of writing "white, white, white, white, white" you just write "5 whites". If the colours keep changing every square, that shortcut doesn't save you anything.

🔑 Key words

Binary
Numbers made only of 0s and 1s.
Hexadecimal
Base-16 shorthand for binary; 1 digit = 4 bits.
Overflow
When a result is too big to fit in the bits available.
Logical shift
Slides bits left/right; empty spaces filled with 0.
Two's complement
Flip every bit, add 1 — makes a number negative.
ASCII / Unicode
Codes for English text / codes for every language.
Sample rate
How many sound measurements per second.
Pixel / Colour depth
One tiny coloured square / bits used to store its colour.
Nibble / Byte
4 bits / 8 bits (2 nibbles).
Lossless / Lossy
Nothing lost / some data thrown away for good.
RLE
Stores repeats as "how many, what" instead of writing them all out.
