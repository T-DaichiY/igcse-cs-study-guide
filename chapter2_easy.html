2.1 Sending data between devices

Packets, routes, one-wire vs many-wire sending, and USB

When you send a big file, the computer chops it into small chunks called data packets before sending it. Each packet can even take a different path to get there.

🍎 In plain words

Think of moving house by putting your things into lots of small boxes instead of one giant crate. Each box (packet) can go in a different van (route) if needed, and gets a label so it can be put back in the right room (reassembled) once it arrives.

What's inside a packet

PartWhat it holds
HeaderWho it's from, who it's going to, and its number in the sequence
PayloadThe actual data being sent
TrailerA marker for "packet ends here", plus a check value (CRC) to test for errors
💡 The CRC works by counting the 1s in the payload before sending, and counting them again after it arrives — if the two counts don't match, something went wrong.

Packet switching — different routes, same destination

Machines called routers pass each packet along, deciding the next step based on which paths are free right now. Because packets can take different routes, they might arrive in the wrong order — the receiving computer uses each packet's number to sort them back out.

Sending in one direction, or both?

ModeMeaningExample
SimplexOne direction onlyComputer → printer
Half-duplexBoth directions, but one at a timeA walkie-talkie
Full-duplexBoth directions at onceA phone call over broadband

One wire, or many wires?

Serial sends bits one at a time down one wire — slower, but reliable over long distances. Parallel sends several bits at once down several wires — faster, but over a long cable the bits can arrive muddled up (this is called skewing).

🍎 In plain words

Serial is like people filing through a single doorway one at a time — orderly but slow. Parallel is like everyone rushing through eight doors at once — fast, but if the doors are far apart, people can get mixed up before they regroup.

USB — the everyday serial connector

USB is a type of serial connection. Plug something in, and the computer automatically detects it and loads the right software (driver) to talk to it.

Good things about USBNot-so-good things about USB
Auto-detects devices, loads drivers itselfCable can only run 5 m before needing a hub
Only fits one way — hard to plug in wrongSlower than some other connections (e.g. Ethernet)
Supplies its own power — no extra plug neededVery old USB devices might not work on new computers
🍎 In plain words

USB-C is the newer connector on most phones and laptops — it's symmetrical, so you never have to flip it over to make it fit.

2.2 Spotting errors

Why mistakes happen, and how computers catch them

Sometimes data gets muddled on its journey — this can happen because of electrical interference, problems while packets are being routed, or bits arriving skewed (out of sync). A computer can't just guess what the data should have said, so it needs ways to check.

🍎 In plain words

A human can still read "Cmabridge Uinervtisy" because our brains recognise whole words. A computer can't do that trick — it needs the data to be exactly right, or clearly flagged as wrong.

Parity check — counting 1s

Sender and receiver agree in advance: every byte should have an even number of 1s, or an odd number. One extra bit (the parity bit) is added to make this true. If the count is wrong when it arrives, an error is flagged.

🧮 Spotting the error
1Byte sent (even parity agreed): 0 1011100 — that's 4 ones. Correct!
2Byte received: 0 1001100 — that's only 3 ones. Odd, when it should be even.
➜ The receiver knows something went wrong.
⚠️ If exactly two bits flip by accident, the count of 1s stays the same — so parity checking misses it completely!

Checksum

Before sending a block of data, the sender does a calculation on it and attaches the answer (the checksum). The receiver redoes the same calculation — if the two answers match, nothing went wrong.

Echo check

The receiver sends the data straight back to the sender, who compares it with what they originally sent.

⚠️ This isn't perfect — if the two copies don't match, you can't tell whether the mistake happened going out, or coming back!

Check digits — catching typing mistakes

A check digit is a bit different: it's not about transmission at all, it's about catching mistakes when a human types a number or a scanner misreads a barcode, like ISBNs on books.

🧮 A quick taste of the ISBN-13 rule
1Add up digits in odd positions.
2Add up digits in even positions and multiply by 3.
3Add both totals, divide by 10, and use the remainder to work out the final check digit.
➜ You won't need to memorise this — in the exam, the steps are given to you.

ARQ — "please send that again"

Automatic Repeat reQuest (ARQ) uses two ideas: an acknowledgement message (says "got it fine" or "that was wrong, resend") and a timeout (if no message arrives in time, resend anyway, just in case).

🍎 In plain words

It's like texting a friend and waiting for a "seen" tick. No tick after a while? You just send it again, to be safe.

2.3 Keeping data safe

Encryption — scrambling data so only the right person can read it

Anything sent over the internet could be intercepted by a hacker (an eavesdropper). Encryption can't stop someone grabbing the data — but it can stop it making any sense to them.

⚠️ Careful with your wording: encryption doesn't make data "unreadable" — you can still see the characters. It makes the data meaningless without the right key.
🍎 In plain words

It's like writing a note in a made-up code. Anyone can still see the squiggles on the page — they just have no idea what it says unless they know the code.

Plaintext and ciphertext

The original message is plaintext. After encryption, it becomes ciphertext — meaningless without the matching decryption key.

Symmetric encryption — one key for both jobs

Symmetric encryption uses the same key to lock (encrypt) and unlock (decrypt) the message.

🧮 A simple shift example

Key 4291362856 shifts each letter forward by that many places.

1C shifted forward 4 → G. O shifted forward 2 → Q.
2"COMPUTER" becomes "GQVQXZGZ".
➜ To undo it, shift each letter back by the same amount.
⚠️ The tricky part isn't cracking the key — it's getting the same secret key safely to both people without anyone else seeing it on the way.

Asymmetric encryption — two keys

Asymmetric encryption uses two different but linked keys: a public key (anyone can have it) and a private key (only the owner keeps it, and it's never sent anywhere).

🧮 Tom sends Jane a secret document
1Jane makes a public key and a private key.
2Jane gives Tom her public key.
3Tom uses it to lock (encrypt) the document and sends it.
4Only Jane's private key can unlock (decrypt) it.
➜ Jane's private key never travels anywhere, so nobody can intercept it.
🍎 In plain words

It's like a padlock and key. Jane hands out open padlocks (public key) to anyone. Anyone can click one shut on a box — but only Jane's own key (private key) can open it again.

🔑 Key words

Data packet
A small chunk of data sent over a network.
Router
Decides which way a packet travels next.
Simplex / Duplex
One way / both ways (at once or taking turns).
Serial / Parallel
One wire, in order / many wires, at once.
USB
The common plug-and-play serial connector.
Parity check
Counts 1s in a byte to spot an error.
Checksum
A calculated value that's checked again after sending.
Echo check
Data is sent back to the sender to compare.
Check digit
Catches typing/scanning mistakes, e.g. in an ISBN.
ARQ
Resend the data if no "got it" message arrives in time.
Plaintext / Ciphertext
Original message / scrambled, encrypted message.
Symmetric / Asymmetric
One shared key / a public key + a private key.
