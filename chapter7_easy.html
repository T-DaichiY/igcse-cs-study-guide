7.1–7.2 Designing a solution

life cycle, abstraction, decomposition
🍎 In plain words

Building a program is like building a Lego set: Analyse (read what’s asked), Design (plan), Code (build), Test (check it works). Abstraction = ignore the unimportant details (a subway map). Decomposition = break a big job into small jobs.

Program development life cycle
Always in this order — and testing often sends you back to an earlier stage.

7.2 Flowcharts & pseudocode

design tools
🍎 In plain words

A flowchart draws your plan with shapes; pseudocode writes it in simple English-like code. Both are for people — a computer can’t run them, but they make coding easy.

Flowchart symbols in action
Oval = start/end · parallelogram = input/output · rectangle = process · diamond = decision.

7.5–7.6 Validation & test data

checking data
🍎 In plain words

Validation asks: “is it sensible?” (e.g. age 1–120). Verification asks: “was it copied correctly?” Test with normal, boundary (edge values) and erroneous (wrong) data.

Validation vs verification
Validation = reasonable? Verification = copied correctly? Neither proves the data is actually true.

🔑 Key terms

Program development life cycle
The stages analysis, design, coding and testing, carried out in order to produce a working program.
Abstraction
Keeping only the details needed to solve a problem and removing unnecessary detail.
Decomposition
Breaking a problem down into smaller component parts: inputs, processes, outputs and storage.
Structure diagram
A design method showing a problem broken into a hierarchy of sub-systems.
Flowchart
A diagram that uses standard symbols to show the steps of an algorithm.
Pseudocode
Structured, language-independent text used to design and write an algorithm precisely.
Linear search
Checking each item in turn, from the start, until the target is found or the list ends.
Bubble sort
Repeatedly comparing adjacent items and swapping them if out of order until the list is sorted.
Totalling / counting
Totalling adds values into a running sum; counting adds 1 each time something happens.
Validation
An automatic check that input data is reasonable: range, length, type, presence, format and check digit.
Verification
A check that data has been entered correctly: visual check or double entry check.
Test data
Normal, abnormal, extreme (largest/smallest acceptable) and boundary (acceptable value plus the nearest rejected value).
Trace table
A table used to dry-run an algorithm, recording variables, outputs and user prompts at each step.
