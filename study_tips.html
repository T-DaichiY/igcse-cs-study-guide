Key messages from the examiner

Straight from the June 2025 Principal Examiner Report for Teachers

Paper 0478/12 (Computer Systems) — Key messages: "Candidates need to show a greater use of technical terminology in their responses. Candidates will also need to note the key terms given in a question and structure their responses using these. Candidates must also use the given context in their responses."

This one sentence explains most of the mark loss seen across the paper. Three separate habits are being asked for:

  • Use technical terminology — say "volatile" not "it forgets", say "parity check" not "it checks for errors".
  • Use the key terms given in the question — if the question says "explain the effect on the image file", your answer should talk about the image file specifically, not files in general.
  • Use the context given — if the scenario is a hospital robot controlled by a human, your answer must relate to that human-controlled robot, not robots in general.

General comments (all Computer Systems papers): "If a candidate writes their response to a question on an additional page, they must indicate very clearly on the script where their response is to be found. If answers are crossed out, any new answer must be written very clearly, so that the text can be easily read." — a simple habit that costs nothing but protects marks that would otherwise be missed by the examiner.

Do's and Don'ts

Built from real Question-by-question examiner comments, June 2025
✅ Do❌ Don't
Show your working for every calculation (binary/hex conversion, two's complement, storage-unit conversion) — marks are allocated for working shown, not just the final answer.Don't just write the final number — many candidates who converted correctly still lost marks because "some candidates did not show their working".
Re-read the question for any reason, fact, or example it already gives you.Don't repeat a reason already stated in the question — e.g. candidates who wrote "quicker to transmit" for a compression question lost the mark because it was already given in the question.
Relate your explanation to the exact scenario in the question (a named file type, a named device, a named person).Don't give a generic textbook answer — e.g. explaining lossless compression using "repeating words in a text file" when the question was about an image file scored no marks.
Use the precise technical name for hardware/software components (e.g. "clock", "arithmetic logic unit", "parity check").Don't confuse similar-sounding terms — e.g. giving "clock speed" (a measurement) instead of "clock" (the component) when asked to name CPU components.
When asked to name/describe two things, make sure each one is genuinely different and matches what was asked.Don't reuse an example that was already given in the question — e.g. giving "RAM" as an example of primary storage when RAM was already named in the question stem.
When describing the role of a function, explain what it actually does for the user/programmer.Don't just reword the function's name — e.g. "auto-completion... auto-completes the code" repeats the name without describing the role.

Good vs weak sample answers

Based on real question types and examiner commentary from June 2025
🧮 "Explain why lossless compression would reduce the size of an image file" (2 marks)
1Weak answer (what many candidates wrote): "Lossless compression finds repeating data and stores it more efficiently, like finding repeated words in a text file." — generic, not related to an image file, scores 0–1.
2Strong answer: "Lossless compression looks for patterns of repeated pixel colours/values in the image data and replaces them with a shorter code, so the file takes up less storage space, and the original image data can be perfectly restored when needed."
➜ Same technique, but the strong answer names the actual data type (pixel/image data) given in the question.
🧮 "Give two electrical components of a robot" then "suggest why a human might do this task instead" (context: human-controlled robot)
1Weak answer: "Robots do not need to take breaks, robots don't get tired." — a generic robot-vs-human answer that ignores the fact the robot in the question is controlled by a human.
2Strong answer: "A human can use judgement in an unexpected situation, which the robot cannot do on its own since it is being directly controlled — the human operator can react appropriately to something the robot's pre-programmed responses would not cover."
➜ The strong answer anchors the point to "controlled by a human" specifically, exactly as the examiner report highlights.

🎯 Quick check — Exam Technique

0 / 5
Question 1
A binary addition question is worth 3 marks and says "show your working". You write only the final binary answer, which is correct. What happens?
Question 2
A question already states "RAM is an example of primary storage" and then asks "give one other example of primary storage". Which answer is safe?
Question 3
A question asks you to explain the effect of a change on an "image file" specifically. What should your answer do?
Question 4
Which is the more accurate term for the CPU component that generates timing pulses to synchronise the fetch-decode-execute cycle?
Question 5
If you write your answer on an extra page because you ran out of space, what must you do?

Key terms

Technical terminology
Precise subject-specific vocabulary (e.g. "volatile", "parity check") that examiners specifically ask candidates to use more of.
Context
The specific scenario given in a question — the strongest answers refer back to it directly rather than giving a generic answer.

📌 Exam tips

Before answering, circle any nouns the question repeats (a device, file type, or scenario) — your answer should use those exact words.

For "show your working" questions, always write every intermediate step, even if you can do it in your head.
