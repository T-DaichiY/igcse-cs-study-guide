1.1 Number systems

Why computers use binary, denary/binary/hex conversions, binary addition, logical shifts and two's complement

Every computer is built from millions of tiny electronic switches that can only be ON or OFF. Computer scientists represent ON with the digit 1 and OFF with the digit 0 — this maps perfectly onto the binary (base 2) number system. Any data a computer works with — numbers, text, sound, images — must first be converted into binary, because the computer's circuitry is built from logic gates (themselves built from switches), and the results are stored in registers that can only hold binary digits (bits).

💡 Answering "why does a computer use binary" questions: link two ideas together — (1) a computer's components are physical switches that can only be ON or OFF, and (2) binary is the number system that uses only two digits (0 and 1), so it maps directly onto those two switch states. Just saying "computers understand 0s and 1s" without the switch/logic-gate link will not gain full marks.

Denary, binary and hexadecimal

Denary (decimal) is our everyday base 10 system, using digits 0–9 with column headings that are powers of 10. Binary is a base 2 system using only 0 and 1, with column headings that double each time. Hexadecimal ("hex") is a base 16 system using 0–9 then A–F for 10–15; because 16 = 2⁴, every hex digit maps to exactly 4 binary bits — the key fact that makes binary ⇌ hex conversion fast.

🧮 Example — denary → binary (two valid methods), convert 142
1Method 1 (subtract powers of 2): 142 − 128 = 14; 14 − 8 = 6; 6 − 4 = 2; 2 − 2 = 0. So 142 = 128+8+4+2.
2Method 2 (divide by 2, read remainders bottom to top): 142÷2=71 r0; 71÷2=35 r1; 35÷2=17 r1; 17÷2=8 r1; 8÷2=4 r0; 4÷2=2 r0; 2÷2=1 r0; 1÷2=0 r1.
➜ Both methods agree: 142 = 1 0 0 0 1 1 1 0
🧮 Example — binary → hexadecimal, convert 10000111111101
1Split into groups of 4 bits from the right: 10 · 0001 · 1111 · 1101.
2Pad the left-most group with 0s: 0010 · 0001 · 1111 · 1101.
3Convert each group: 0010=2, 0001=1, 1111=F, 1101=D.
➜ = 2 1 F D (hex)
⚠️ Common misconception (June 2025 Examiner Report, Paper 0478/11): when converting a two-digit hex number such as "14" to binary, some candidates tried to convert the whole number "14" as if it were denary, instead of converting each hex digit (1 and 4) individually into its own 4-bit group. Always convert hex digit by digit.

Uses of hexadecimal

Binary numbers are long and hard for humans to read accurately — a single byte is already 8 digits. Because one hex digit exactly represents four binary digits, hex is roughly a quarter of the length of the equivalent binary number, making it much easier for humans to read, copy and spot errors in.

📌 Answering "why is hexadecimal used" questions: link two ideas — (1) hex is a much shorter/more compact representation than the equivalent binary, and (2) this makes it easier for a human to read, remember, type and spot errors in, while still converting cleanly back to binary. Saying only "it's shorter" earns partial credit at best.

⚠️ Overflow. An 8-bit register can only store values 0–255. If adding two 8-bit numbers produces a result greater than 255, the addition generates a 9th bit that cannot be stored — it is lost, and the remaining 8 bits give a value that is too small. This is an overflow error: e.g. 110 + 222 = 332, which cannot fit in 8 bits. A full-mark explanation states both that the result is greater than 255, and that the register/number of bits available is a fixed, limited size.

Logical binary shifts

A logical shift moves every bit in a register one or more places left or right. Each left shift multiplies the value by 2; each right shift divides it by 2 (rounding down). The position(s) vacated are always filled with zeros; bit(s) that fall off the opposite end are simply lost.

A logical shift always fills the vacated end with zeros — never with 1s, and never with the bit(s) that were lost.

Two's complement — representing negative numbers

Two's complement represents positive and negative integers in binary. The only change from ordinary binary is that the left-most bit's column heading becomes negative — worth −128 in an 8-bit number. A 0 in this position means positive; a 1 means negative.

1.2 Text, Sound and Images

Character sets (ASCII/Unicode), sampling sound, and bitmap image representation

Just like numbers, text, sound and images must all be converted to binary before a computer can store or process them.

Character sets — ASCII and Unicode

A character set is an agreed table that assigns a unique binary code to every character a computer needs to represent. ASCII (American Standard Code for Information Interchange) uses 7-bit codes (0–127) for the standard keyboard, plus 32 control codes. Extended ASCII uses the full 8 bits (0–255) for extra non-English and graphical characters.

CharacterBinary (7-bit)Hex
a110000161
A100000141
💡 Comparing a and A, only the sixth bit changes between lower and upper case, making case-conversion fast and simple. Characters within a group (a–z, 0–9) are also stored in sequence, which speeds up sorting and comparison.

Unicode was created to overcome ASCII's limits: it can represent characters from every language in the world (plus symbols and emojis), using up to 4 bytes per character. Unicode's first 128 characters are identical to ASCII, so ASCII text is automatically valid Unicode text.

📌 Answering "compare ASCII and Unicode" questions: link the range of characters directly to the number of bits used — Unicode supports far more characters and languages precisely because it uses more bits per character than ASCII. Stating the two facts as unconnected observations only earns partial credit.

Representing sound

Sound is a continuously varying (analogue) signal and must be converted to digital using an analogue-to-digital converter (ADC), a process called sampling — the wave's amplitude is measured at regular time intervals and stored as a binary number.

⏱️
Sample rate
Number of samples taken per second, measured in Hertz (Hz)
📏
Sample resolution (bit depth)
Number of bits used to store each sample's amplitude value
⚠️ Common confusion (June 2025 Examiner Report, Paper 0478/13): "hertz" and "frequency" describe sample rate only — never use them as an answer for sample resolution (bit depth). Learn the two terms as a precise pair: rate = samples per second (Hz); resolution = bits per sample.
Sampling an analogue sound wave
The ADC reads the wave's height at fixed time intervals (sample rate) and rounds each reading to the nearest value it can store (sample resolution).
🧮 Worked example — mono sound file size

File size (bits) = sample rate × sample resolution × duration (seconds). A recording lasts 10 seconds, sampled at 8000 Hz with 8-bit resolution, mono.

18000 × 8 = 64 000 bits per second.
2× 10 seconds = 640 000 bits.
3÷ 8 to get bytes: 640 000 ÷ 8 = 80 000 bytes.
➜ 80 000 bytes (for stereo, double this to 160 000 bytes)

Representing bitmap images

A bitmap image is stored as a two-dimensional grid of pixels, each pixel stored as its own binary number.

🎨
Colour depth
Bits used to represent the colour of one pixel. With x bits, 2ˣ colours can be shown — 8 bits = 256 colours; 24 bits = over 16 million
🖼️
Resolution
The total number of pixels making up the image, e.g. 4096 × 3072 = 12 582 912 pixels
💡 A lower resolution means less detail — the image can look "pixelated" or fuzzy when there aren't enough pixels to represent it clearly. Increasing either resolution or colour depth improves quality but also increases file size, since more binary numbers must be stored.
A bit-map image zoomed in — each square is one pixel
Each square is one pixel; its colour is stored as a binary code. More pixels (resolution) and more bits per pixel (colour depth) both make the file bigger.
🧮 Worked example — bitmap file size

File size (bits) = resolution (pixels) × colour depth (bits). A camera sensor has a 2048 × 2048 pixel array with a colour depth of 16 bits.

1Total pixels: 2048 × 2048 = 4 194 304.
2× colour depth: 4 194 304 × 16 = 67 108 864 bits.
3÷ 8 for bytes: 67 108 864 ÷ 8 = 8 388 608 bytes; ÷ 1 048 576 for MiB: 8 388 608 ÷ 1 048 576 = 8 MiB.
➜ 8 388 608 bytes (8 MiB)

1.3 Data Storage and Compression

Measuring storage in IEC units, calculating file size, and lossy/lossless compression

Measurement of data storage

A bit is the smallest unit of memory — a 0 or a 1. A nibble is 4 bits. A byte is 8 bits (2 nibbles) — the smallest unit of memory normally addressed by a computer. The 0478 syllabus uses the IEC binary-based system, where each unit is exactly 1024 times the previous one (1024 = 2¹⁰), not 1000.

UnitBytes
1 kibibyte (KiB)2¹⁰ = 1 024
1 mebibyte (MiB)2²⁰ = 1 048 576
1 gibibyte (GiB)2³⁰ = 1 073 741 824
1 tebibyte (TiB)2⁴⁰
1 pebibyte (PiB)2⁵⁰
1 exbibyte (EiB)2⁶⁰
⚠️ 1024, not 1000. Never use 1000 as the multiplier for these units, even though some marketing (e.g. hard-disk packaging) uses the older SI (kilo/mega/giga) system — that system is not what this syllabus tests. Also memorise "1 byte = 2 nibbles" — the June 2025 report shows "4" was the most common wrong answer.

Calculation of file size

Image file size (bits) = resolution (pixels) × colour depth (bits). Mono sound file size (bits) = sample rate (Hz) × sample resolution (bits) × duration (seconds); for stereo, double the mono result.

🧮 Worked example — stereo sound file size in MiB

An audio CD track: 44 100 Hz sample rate, 16-bit resolution, stereo, lasting 3600 seconds (60 minutes).

1Mono bits: 44 100 × 16 × 3600 = 2 540 160 000 bits.
2Double for stereo: 2 540 160 000 × 2 = 5 080 320 000 bits.
3÷ 8 for bytes: 635 040 000 bytes; ÷ 1 048 576 for MiB ≈ 605 MiB.
➜ ≈ 605 MiB
📌 Non-negotiable calculation rules: (1) give the answer in the exact unit the question specifies; (2) always divide by 1024, never 1000; (3) remember the division by 8 to convert bits into bytes before converting further. Show every step as separate working — Cambridge mark schemes typically award marks for intermediate steps, not just the final answer.

💡 When asked for reasons to compress a file, name the specific benefit (e.g. "less bandwidth used") rather than a vague catch-all like "it makes the file smaller" — size reduction is the mechanism, not the reason. If a question already states one reason, don't repeat it back when asked for "another" reason.

Lossy and lossless compression

FeatureLossy compressionLossless compression
Original file recoverable?No — data permanently removedYes — fully reconstructed
Resulting file sizeSmallerLarger (than lossy equivalent)
Typical useMusic (MP3), video (MP4), photos (JPEG)Spreadsheets, applications, RLE-encoded images
Example mechanismReduce resolution/colour depth/sample rate/resolutionRun-length encoding (RLE)

MP3 uses "perceptual music shaping" to remove sounds humans can't perceive (frequencies outside hearing range, and quieter sounds masked by louder ones), shrinking files by about 90%. JPEG exploits the eye's lower sensitivity to colour than brightness.

Run-length encoding (RLE) is lossless: it replaces a run of adjacent, identical data with a (count, code) pair.

🧮 Worked example — RLE on "aaaaabbbbccddddd"
1Original: 17 characters, 1 byte each = 17 bytes uncompressed.
2Group into runs: 5×'a' (97), 4×'b' (98), 2×'c' (99), 5×'d' (100).
3Encode as pairs: 05 97 · 04 98 · 02 99 · 05 100 — 4 pairs = 8 bytes.
➜ 17 bytes compressed to 8 bytes — under half the original size
⚠️ RLE only saves space where there are long runs of repeats. A string like "cdcdcdcdcd" has no repeated runs — plain RLE gives no useful compression and can even grow the data. A flag byte (e.g. 255) is used to tell a decoder that the following values are a genuine count-and-code pair, so single non-repeating values aren't wrapped in a wasted run-of-1.
📌 Answering "explain how lossless compression works" questions in context: the June 2025 report shows many candidates lost marks by explaining RLE using a generic "repeating words in a text file" example when the question was about an image. Always adapt the explanation to the specific file type given — for an image, describe repeating pixels/colours being grouped and stored with a repeat count.

📌 Exam tips

Always show your working for conversions and file-size calculations — marks are for method, not just the final answer.

State clearly whether overflow has occurred, and why (result > 255 AND the register has a fixed size), when adding two's-complement numbers.

Learn the two file-size formulas cold: image = resolution (pixels) × colour depth; sound = sample rate × resolution × duration × (×2 for stereo). Always divide by 1024, never 1000.
