At IGCSE you only study the single-table database. SQL is the part that carries the most marks — and the part where the most marks are thrown away.

9.1.1 What a Database Is, and Why We Use One

A database is a structured collection of data that lets people extract information in a way that meets their needs. A single-table database contains only one table; relational (multi-table) databases are A Level.

💡 Exam Tip — Never Answer With One Word.

Three reasons to use a database, each with its mechanism:

  • Consistency — a change or addition only has to be made once, so the data cannot disagree with itself.
  • Shared access — the same data can be used by everyone who needs it.
  • No duplication — data is only stored once (in relational databases).

"Consistent" on its own scores nothing. "Consistent, because an update only needs to be made in one place" scores the mark.

Databases typically store people (patients, pupils), things (cars, books) or events (bookings, race results).

💡 Field-Naming Rule.

Field names are a single word with no spaces, written in CamelCase to stay readable: BedNumber, not "Bed Number" or "bed number".

9.1.1 Validation Inside a Database

Validation is an automated check by software that entered data is reasonable or within allowed limits. It does not check the data is actually correct — that is verification's job (Chapter 7).

Provided automatically by the softwareMust be set up by the developer
A Date/Time field will only accept a valid dateA range check on WardNumber to allow only 1–10
⚠️ Common Mistake — "The Data Type Is the Validation".

Choosing integer is not validation. A data type restricts the kind of value (whole numbers only); it does nothing about range or format. A WardNumber field typed as integer will happily accept 999 until you add a separate range-check rule of 1 to 10.

9.1.2 The Six Basic Data Types

Every field needs a data type. It decides how the value is stored and displayed, and what operations can be performed on it. These six are the exact syllabus terms — learn them, and their Access equivalents.

Syllabus typeHoldsExample fieldIn Access
text/alphanumericA number of characters: letters, digits, symbolsFamilyName, Addressshort/long text
characterA single character onlyGender (M/F)short text, size 1
BooleanOne of two values: True/False, 1/0, Yes/NoSubwayYes/No
integerA whole numberWardNumber, Populationnumber, 0 d.p.
realA decimal numberAverageIncome, pricenumber, decimal
date/timeA date and/or a timeDateOfAdmissionDate/Time
⚠️ Common Mistake — character vs text.

character holds exactly one character; text/alphanumeric holds a string of one or more. If a field could ever need more than one character, character is wrong — even if every value entered so far happens to be a single letter.

💡 Exam Tip — Always Give a Reason.

Data-type questions carry reason marks. Write "Boolean, because Subway can only ever be one of two states", never just "Boolean". The deciding factor is what operations the value must support, not what it looks like — a numeric-looking ID code can be text if you never do arithmetic on it.

Each field used must be different across the four answers. Reusing Identification for both integer and text loses a mark, even though either would be defensible on its own.

9.1.3 Primary Keys

A primary key is a field that uniquely identifies each record. There is exactly one test to apply:

A field can be the primary key ONLY IF its values are NEVER repeated.
RouteWhen to use itExample
Reuse an existing fieldOne field the table already needs is guaranteed uniqueISBN in a BOOK table
Add a new fieldNo existing field is guaranteed uniqueAdd HospitalNumber to PATIENT
📘 Worked Example — Adding a Key to PATIENT

None of FirstName, FamilyName, DateOfAdmission, Consultant, WardNumber or BedNumber is guaranteed unique — two patients could share a name, or be admitted by the same consultant on the same day. So:

  • Add a new field HospitalNumber
  • Data type text — it has a fixed format, and is never used in calculations
  • Validation: exactly 8 characters, "HN" followed by 6 digits, e.g. HN123456
⚠️ Exam Technique — "State, With a Reason".

Primary-key questions are always phrased "state, with a reason". Never just name the field. Before answering "yes", actually scan the sample data for duplicates — a field that looks unique in three rows may repeat further down. If nothing is unique, say so explicitly and propose a new field rather than forcing an unsuitable one.

9.1.4 SQL — The Commands You Need

Structured Query Language (SQL) is the standard language for writing scripts that pull useful information out of a database. An SQL script is a list of SQL commands that perform a given task, often saved so it can be reused.

CommandPurposeRequired?
SELECTFetches the specified fields (columns); every query begins hereMandatory
FROMIdentifies which table to useMandatory
WHEREIncludes only records (rows) matching a conditionOptional
ORDER BYSorts results by a column — ascending by default, DESC for descendingOptional
SUMReturns the total of all values in a numeric fieldOptional
COUNTCounts the records where the field matches a conditionOptional
SELECT Field1, Field2 ← the columns to display (or * for all) FROM TableName ← which table WHERE Condition ← which rows ORDER BY Field DESC; ← sort order, then a SEMICOLON

The literal value in a condition must be written in a form that matches the field's data type:

Operators available: =, >, <, >=, <=, <> (not equal), BETWEEN, LIKE, IN, AND, OR, NOT.

⚠️ Common Mistake — The #1 Way Marks Are Lost.

Examiner report, June 2025 Paper 22 Q9(b): "A common mistake seen was candidates missing off the quotation marks around the search criteria 'Asia', which was a string." Every keyword can be right and you still drop the mark. Quote every text and date value.

9.1.4 Worked SQL Examples

📘 1 — Filter With WHERE

List the hospital number, first name and family name of Mr Smith's patients:

SELECT HospitalNumber, FirstName, FamilyName FROM PATIENT WHERE Consultant = 'Mr Smith';
📘 2 — Add a Sort With ORDER BY

The same list, alphabetically by family name (ascending is the default, so no keyword needed):

SELECT HospitalNumber, FirstName, FamilyName FROM PATIENT WHERE Consultant = 'Mr Smith' ORDER BY FamilyName;
📘 3 — SUM and COUNT
SELECT SUM(Badges) FROM CUB; → one number: the total badges of all cubs SELECT COUNT(Six) FROM CUB WHERE Six = 'Red'; → one number: how many cubs are in the red six

SUM adds up values; COUNT counts rows. They return a single figure, not a list of records.

9.1.4 Exam question & table design

applying it

9.1.4 Real Exam Question — June 2025 Paper 22 Q9(b)

📘 Worked Example — 4 Marks

"Complete the SQL statement to list only the name, country and population of all the cities in CapitalCity from the continent of Asia. [4]"

SELECT Name, Country, Population FROM CapitalCity WHERE Continent = 'Asia';

One mark each for: all correct fields in SELECT · correct use of FROM · correct field in WHERE (Continent) · correct quoted criterion ('Asia').

💡 The Four A* Rules for SQL.
  • Quote every text and date literal in a WHERE condition.
  • List only the fields asked for, in the order requested — never SELECT * when specific fields are named.
  • Match the field name's exact spelling and capitalisation from the table definition.
  • When asked to give the output of a query, write the data only — no quotation marks or query punctuation in the results.

Designing a Table From a Scenario — The 5-Step Method

  • 1. List every distinct piece of information to be stored about each person/thing/event.
  • 2. Turn each one into a field with a single-word, meaningful name (DateOfBirth).
  • 3. Give the table a meaningful name (CUB).
  • 4. Check whether any field is guaranteed unique; if not, add a primary-key field (CubNumber).
  • 5. Choose a data type for every field, and add the validation rules each one needs.
💡 Examiner's Key Message (June 2025, Paper 0478/22).

"Candidates who read the questions carefully before answering, then ensured that they fully answered the questions that were asked, in an appropriate context, achieved better marks than candidates who gave generic responses."

🔑 Key terms

Database
A structured collection of data. At IGCSE you study a single-table database.
Field
A single column of a table: one item of data about each record.
Record
A single row of a table: all the data about one item.
Validation (database)
A check that data entered in a field is sensible, e.g. range or type.
Data types
Text/alphanumeric, character, Boolean, integer, real and date/time.
Primary key
A field whose value is unique for every record and so identifies it.
SQL
Structured query language, used to query data stored in a database table.
SELECT … FROM … WHERE
SELECT chooses the fields, FROM names the table and WHERE gives the condition for records.
ORDER BY
Sorts the results in ASC (ascending) or DESC (descending) order.
SUM / COUNT
SUM adds the values in a field; COUNT gives the number of records.
AND / OR
Combine conditions in WHERE: AND needs both true, OR needs at least one true.
