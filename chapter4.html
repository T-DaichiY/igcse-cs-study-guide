4.1 System Software and Operating Systems

System vs application software, the nine OS functions, booting up, and interrupts

System software vs application software

Software divides into exactly two categories. System software provides the platform the computer itself needs to work (the operating system and utility software). Application software lets the user carry out a specific task on top of that platform (a word processor, a game, a browser).

💡 Services test. Ask "who does this serve?" System software provides services the computer requires to function at all. Application software provides services the user requires to complete a task. Always phrase a "describe the difference" answer this way — naming an example alone doesn't answer the question.
System software (examples)Application software (examples)
Operating system — Windows, Mac OSWord processor — Microsoft Word
Utility programs — anti-virus, defragmenter, back-up, screensaverSpreadsheet — Microsoft Excel
Device drivers — printer driver, mouse driverDatabase — Microsoft Access
Compilers, interpreters, assemblers, linkersInternet browser, games, photo/video editors
🦠

Compares files against a virus database, plus heuristic checking for suspicious behaviour not yet on the database; infected files go into quarantine
🧩

Rearranges scattered file blocks on an HDD into contiguous sectors so the read-write head moves less — not needed on SSDs
💾

🔐

🖨️

🖥️

⚠️ Do not default to "utility software" as a catch-all answer for a system-software question — the June 2025 examiner report flags this as the most common wrong answer when the correct answer was simply "operating system". Utility software is only one category of system software, alongside the OS and device drivers.

The operating system — nine functions

The operating system (OS) is the software that lets a computer function correctly and lets a user communicate with it, providing a platform for every application to run on. It is normally stored on the HDD/SSD (or solid-state storage on a phone/tablet) because it is a large program. The syllabus groups its work into nine named functions.

#OS functionWhat it actually does
1Human computer interface (HCI)Provides a CLI or GUI so the user can communicate with the computer
2Memory managementAllocates memory to processes; prevents two processes using the same location at once
3Security managementEnsures integrity, confidentiality and availability of data via passwords, updates, firewalls
4Hardware/peripheral managementAllocates data to buffers; transmits/receives data to/from hardware via drivers
5File managementCreate, open, close, delete, rename, copy, move files; maintains directories and access rights
6Handling of interruptsReceives, prioritises and services interrupt signals (see below)
7Platform for applicationsAllows application software to run on the computer
8MultitaskingShares CPU time between processes using pre-emptive multitasking and priorities
9User accountsUsername/password-protected accounts, managed by an administrator; multi-access levels
💡 Name + description. A "give two/three functions" question is one mark per named function. But a table-style or "describe" question wants a name and a working example together — e.g. not just "memory management" but "allocates memory to processes / prevents two processes accessing the same memory location". A bare name alone may not earn the mark if a description is asked for.

Running applications — hardware, firmware, OS, application

An application cannot run on its own — it depends on a strict chain of layers, each running on the one below it.

📌 Chain order: applications run on the OS → the OS runs on the firmware → the firmware (bootloader) runs on the hardware. Getting the direction backwards (e.g. "the OS runs the firmware") loses marks even if every term used is correct.
🖥️ Booting up a computer
1Power on. The BIOS (Basic Input/Output System) — firmware, "a program that provides low-level control for devices" — starts up the motherboard.
2The BIOS locates the storage device holding the operating system.
3A small program, the bootstrap loader, loads the needed part of the OS into RAM — this is "booting up".
4Once the OS is running, applications can run on top of it.
➜ Hardware powered on → BIOS (firmware) runs → bootstrap loader loads the OS → applications run on the OS
WhatStored onIf power is lost
BIOS software (the program itself)EEPROM — a flash memory chipContents remain unaffected
BIOS settings (e.g. boot order, clock speed)CMOS chip, kept powered by a motherboard batterySettings reset to factory default if the battery is disconnected
⚠️ Examiners specifically report that "firmware" is poorly defined by candidates. Give the precise definition — "a program that provides low-level control for devices" — not a vague "software on the computer".

Interrupts

An interrupt is a signal sent from hardware or software to the microprocessor, causing it to temporarily stop what it is doing so the interrupt can be serviced.

Hardware interruptsSoftware interrupts
A key being pressed / mouse movedTwo processes trying to access the same memory location
A regular timing/clock signalAn attempt to divide by zero
A hardware fault, e.g. a printer paper jamAn .exe file that cannot be found to start a program
⚠️ Documented misconception (June 2025 Examiner Report, 0478/11): "Some candidates gave responses such as 'keyboard' or 'mouse'. These are just devices and not examples of interrupt." Always name the event on the device (e.g. "a key being pressed"), not just the device itself.
🧮 How an interrupt is serviced (the ISR process)
1The processor finishes its current fetch–decode–execute cycle.
2It checks the interrupt queue: is there an interrupt with higher priority than the current task?
3If yes, it saves the current task's Program Counter and registers, then loads the start address of the interrupt service routine (ISR) into the PC.
4The ISR runs and resolves the interrupt.
5The saved registers are restored and the original task continues from where it left off.
➜ Skipping the priority-check step or the save/restore-registers step is the most common way marks are lost on "describe how an interrupt is handled" questions.

Buffers — a memory area that stores data temporarily — let a fast processor cooperate with a slow device (e.g. a printer). Data is written to the buffer; the buffer is emptied to the device while the processor is freed for other tasks; once the buffer empties, an interrupt requests more data.

💡 Without buffers and interrupts, the processor would sit idle waiting for a slow device (like a printer) to finish — an enormous waste of processing power.

4.2 Languages and Translators

High-level vs low-level languages, assembly language, compilers, interpreters and IDEs

A computer only understands its own language, machine code — every program must be translated into machine code before it can run.

High-level vs low-level languages

High-level language (HLL)Low-level language (LLL)
Independent of computer hardware (portable/machine independent)Dependent on the specific hardware and instruction set of a computer
Statements close to English — easier to read, write, debug and maintainHarder to read and debug; may use mnemonics (assembly) or raw binary/hex (machine code)
Quicker to write programs; more portable across computersCan directly manipulate hardware and use machine-specific instructions
Programs may be larger and take longer to executeMore memory-efficient, and executes/runs faster once translated
Examples: C++, Java, Pascal, Python, Visual BasicExamples: assembly language, machine code
💡 Four-way rule. An "advantages/disadvantages of high-level vs low-level" answer should cover: (1) ease of reading/writing, (2) ease of debugging, (3) machine independence, (4) direct hardware manipulation (only low-level can do this). A one-sided answer misses marks.
⚠️ Never repeat a reason already given in the question stem — a real June 2025 examiner report confirms candidates lost marks for restating "easier to read/write" when the question had already stated it. MCQ distractors are also built by swapping a low-level advantage into a high-level question (and vice versa) — sort each property into the correct column before answering.

Assembly language

Assembly language is a low-level language that uses mnemonics — short, memorable codes — instead of raw machine code. An assembler translates it into machine code; one assembly statement usually becomes exactly one machine code instruction (unlike a high-level statement, which usually becomes several).

🧮 Adding two numbers in assembly language
1LDA First — load the value of First into the accumulator.
2ADD Second — add the value of Second to the accumulator.
3STO Sum — store the accumulator's value into Sum.
➜ Equivalent to the high-level statement Sum := First + Second, but written using hardware-level mnemonics.
📌 Programmers choose assembly language for embedded systems needing direct hardware control, machine-specific instructions, a small memory footprint, or fast execution — e.g. an embedded system in a washing machine.

Compilers, interpreters and assemblers

CompilerInterpreter
What it doesTranslates the whole high-level program at once, before executionTranslates and executes the code line by line
Executable file?Yes — produces a standalone executable fileNo executable file — the interpreter must be present every run
ErrorsProduces one error report listing all errors, before execution can happenStops execution at the first error found
Typical useTranslating the finished, final program for distributionUsed mostly while developing/testing a program
Speed once readyFaster to run (already translated)Slower — translated every run; but faster to fix errors while coding
💡 Core phrasing to memorise: compiler = "translates the whole code at once, before executing it, and produces an executable file." Interpreter = "translates and executes the code line by line, stopping when an error is found." An assembler does the compiler's job but for assembly language, not a high-level language.
📌 Development vs deployment framing. An interpreter suits development — errors are found and fixed one line at a time. A compiler suits the finished program — the executable runs without the compiler present, runs faster, and can be distributed without exposing the source code.
🧮 Fill-in-the-blank translator question (June 2025, 0478/12)
1"A compiler translates the whole code at once before executing it."
2"A compiler produces an error report that displays all errors."
3"An interpreter translates and executes the code line by line."
4"An interpreter stops execution when an error is found and continues once it is corrected."
➜ Fill-in-the-blank translator questions reward exact vocabulary — "whole code", "line by line", "executable file", "error report" — not paraphrases.

Integrated Development Environment (IDE)

An IDE is a suite of programs that helps a programmer write and test code — e.g. PyCharm (Python), Visual Studio (Visual Basic), BlueJ (Java).

IDE featureWhat it actually does (the mechanism, not the name)
Code editorLets the programmer write/change code without a separate text editor
Translator (compiler/interpreter)Built in so the program can be run; interpreter used while developing, compiler for the final version
Run-time environment / debuggerRuns the program, allows single-stepping and breakpoints, and shows variable contents in a report window
Error diagnostics / auto-correctionFlags likely errors as code is typed and offers a suggested fix, before the program is even run
Auto-completionAs the programmer starts typing a command word or variable name, the IDE suggests options to complete it
PrettyprintColour-codes command words/identifiers and lays code out consistently, so it's easier to read
⚠️ Real, documented examiner evidence (June 2025, 0478/12): "Some candidates gave the function 'auto-completion', then gave the description 'it auto-completes the code written'. Candidates need to describe the role of the function beyond rewording the function." Always describe the underlying mechanism — a command word being typed and the IDE suggesting matching options — not just restate the feature's name. Also, don't confuse IDE functions with operating-system functions: an IDE helps write and test code; an OS manages hardware and resources.

🔑 Key terms

System / Application software
Services the computer requires / services the user requires.
Utility program
System software managing resources — anti-virus, defrag, back-up, screensaver.
Device driver
Translates data so a peripheral can communicate with the OS.
Operating system
Provides a platform for applications and an interface for the user.
Firmware / BIOS
Low-level control program that boots the motherboard and finds the OS.
EEPROM / CMOS
BIOS program storage / battery-backed BIOS settings storage.
Interrupt
A signal to the processor requesting attention, given a priority.
Interrupt service routine (ISR)
Code that handles/resolves an interrupt.
Buffer
Temporary memory area matching a fast processor to a slow device.
High-level / Low-level language
Machine independent, readable / hardware-specific, e.g. assembly.
Mnemonic
Short code (LDA, ADD, STO) representing a machine operation.
Compiler / Interpreter / Assembler
Translate whole program at once / line by line / assembly → machine code.
IDE
Suite of tools to write and test code: editor, translator, debugger, diagnostics.
Prettyprint
Colour-codes and formats source code for readability.

📌 Exam tips

Describing IDE features? Go beyond the feature's name — explain the actual mechanism, e.g. auto-completion suggests matches as you type a command word, not "it auto-completes the code".

Never restate a reason already given in the question stem — examiners confirm this specifically loses the mark.

For interrupts, always give the event on a device ("a key pressed"), never just the device name ("keyboard").
