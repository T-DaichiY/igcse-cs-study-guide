3.1 CPU Architecture

The CPU, Von Neumann architecture, cores/cache/clock, instruction sets and embedded systems

The central processing unit (CPU)

The central processing unit (CPU) — also called a microprocessor or processor — is central to every modern computer system, including tablets and smartphones. It is responsible for the execution or processing of all the instructions and data in a computer application. Without a CPU, a computer cannot run any software at all.

Component groupRole
Control unit (CU)Directs and synchronises the operation of the whole CPU by sending out control signals.
Arithmetic and logic unit (ALU)Carries out arithmetic (e.g. +, −) and logic (e.g. AND, OR) operations.
Registers and busesRegisters temporarily hold data/instructions inside the CPU; buses carry data, addresses and control signals between components.
⚠️ Command-word discipline. A full-mark answer for "describe the role of the CPU" must say the CPU processes/executes instructions and data — not simply "it controls the computer" or "it is the brain of the computer". Vague analogies earn no technical marks on their own.

A microprocessor is the CPU implemented as a single integrated circuit (chip). This differs from a microcontroller (a CPU plus RAM, ROM and other peripherals on one chip, dedicated to one task, e.g. a digital watch) and a system on chip (SoC) (a microcontroller plus even more components on one chip) — see the embedded systems section below.

Von Neumann architecture — the stored program concept

Early computers had to be fed data while running and couldn't store programs. In the mid-1940s John von Neumann developed the stored program computer concept, still the basis of computer architecture today: a CPU that can access memory directly; memory that stores programs as well as data; and stored programs made of instructions executed in sequential order.

RegisterAbbreviationFunction
Program counterPCStores the address where the next instruction to be read can be found.
Memory address registerMARStores the address of the memory location currently being read from or written to.
Memory data/buffer registerMDRStores data just read from memory, or about to be written to memory.
Current instruction registerCIRStores the current instruction being decoded and executed.
AccumulatorACCStores the result of an ALU calculation — not the calculation itself.
⚠️ Common misconception (Cambridge 0478 June 2025, Paper 11, Q5a). Some candidates incorrectly stated that the accumulator "stores calculations". The correct description: the accumulator stores the result of a calculation, not the calculation process itself.
BusDirectionCarries
Address busUnidirectional (CPU → memory)Memory addresses. Wider bus = more locations addressable directly (16-bit → 2¹⁶ = 65,536 locations).
Data busBidirectionalData (address, instruction or value) between CPU, memory and I/O devices. Wider = larger "words" carried, better performance.
Control busBidirectionalSignals from the CU to all other components; typically 8 bits wide.
🧮 The fetch–decode–execute (FDE) cycle
1Fetch: the PC's address is copied to the MAR (via the address bus); the instruction at that address is copied from memory into the MDR; the MDR's contents are copied into the CIR; the PC is incremented by 1.
2Decode: the instruction now in the CIR is decoded so it can be interpreted.
3Execute: the CPU sends the decoded instruction as control signals (via the control bus) to the appropriate components, carrying it out.
➜ Full marks require the order PC → MAR → memory → MDR → CIR, and stating the PC increments before the next fetch.

Cores, cache and internal clock — what affects CPU performance

Several factors work together to determine CPU speed — increasing one alone rarely gives a proportional performance gain.

⏱️
Clock speed
The system clock synchronises all operations (e.g. 3.5 GHz = 3.5 billion cycles/second). Higher clock speed increases processing speed, but overclocking beyond design limits risks instability and overheating.
📦
Cache
Fast memory located inside the CPU that stores frequently used instructions/data. The CPU checks cache before RAM. Larger cache = better performance.
🧩
Number of cores
A core = ALU + control unit + registers. Dual/quad core reduces reliance on raw clock speed, but doubling cores doesn't double performance — cores must communicate, which costs time.
💡 Summary rule. For "explain how X affects CPU performance", always state both the direction of the effect and a limiting factor — e.g. "increasing clock speed increases processing speed, BUT can cause overheating/instability if overclocked." A one-sided answer drops marks.
⚠️ Real examiner evidence (Paper 0478/11, June 2025, Q5c). "Some candidates incorrectly stated that [higher clock speed] would mean more fetch-decode-execute cycles could be carried out simultaneously." FDE cycles on a single core happen one after another, faster — not in parallel. Also, per the Paper 0478/12 report: "Some candidates inaccurately gave 'clock speed' instead of 'clock' for controlling the number of FDE cycles" — clock speed is a measurement, not a component.

Instruction set

Every operation is made of an opcode (what to do) and an operand (the data, register or memory location to act on). The instruction set is the complete, limited list of opcodes a particular CPU can process, expressed in machine code. X86 is one common standard — Intel and AMD CPUs use almost identical X86 instruction sets even though their internal electronic designs differ.

📌 Do not confuse an instruction set with programming code. Instruction sets are low-level machine code; high-level program code needs a compiler/interpreter to convert it into instructions the instruction set understands.

Embedded systems

An embedded system is hardware plus software designed to carry out a specific, dedicated set of functions — unlike a general-purpose computer, which can run many different programs. Embedded systems are based on a microcontroller (CPU + RAM/ROM + peripherals on one chip), a microprocessor (CPU chip only, needing separate RAM/ROM), or a system on chip (SoC, which usually includes CPU, memory, I/O ports and storage together).

BenefitsDrawbacks
Small, low cost, low powerHard to upgrade/troubleshoot — a specialist task
Simple, dedicated interface — no OS neededInterface can look simple but be confusing to use
Fast reaction to changing input; reliable (mass produced)Internet-connected devices are open to hackers/viruses
⚠️ Real examiner evidence (Paper 0478/12, June 2025, Q4b). "Most candidates referred to the computer having more than one set task [but] need a greater understanding of the features of an embedded system beyond it being designed to perform a dedicated function." A full-mark answer needs a second, independent distinguishing point — e.g. dedicated vs general-purpose hardware, ease of reprogramming, or "built into a larger device" vs standalone — not two versions of the same point.
🧮 Real examples of embedded systems
1Motor vehicles: fuel injection, airbags, ABS braking, traction control, in-car entertainment/GPS.
2Vending machines: a microcontroller reads a keypad, coin counter, tilt sensor and temperature sensor, and controls motors, a display and a wireless modem.
3Security systems: a controller reads temperature/pressure/acoustic sensors plus a keypad, and produces alarm/light outputs; settings are held on SSD (not RAM) so they aren't lost when powered off.
➜ Note: a computer is NOT an embedded system, because it is multi-functional and can be repurposed by running different software.

3.2 Input, Output and Sensors

Input devices, output devices, and the sensors that link a computer to the physical world

Input devices

Input devices let data enter a computer system. Match the device to why it fits the context — a mechanism description alone, without linking it to the scenario given, won't earn full marks.

📊
Barcode / QR scanner
Red laser/LED reads reflected light off dark/light bars via photoelectric cells. QR codes hold far more data (up to 4296 characters) and are read by a smartphone camera + app.
📷
Digital camera
Light hits a CCD (millions of photodiodes = pixels), converted via an ADC — an 8-bit ADC gives 256 brightness levels per pixel; 24-bit RGB gives full colour.
⌨️
Keyboard
A membrane detects which key completes a circuit; the CPU looks up an index file for the ASCII value. Frequent use risks RSI (repetitive strain injury).
🎤
Microphone
Sound vibrates a diaphragm/coil in a magnetic field, inducing an analogue current; a sound card's ADC digitises it.
🖱️
Optical mouse
A red LED bounces light off the surface; a CMOS + DSP calculate coordinates from up to 1500 images/second. No moving parts, more reliable than mechanical.
🖥️
Touch screen
Capacitive (electrostatic field, multi-touch, best in sunlight), infra-red (broken beams, multi-touch), or resistive (two layers make contact, works with gloves, no multi-touch).
⚠️ Real examiner evidence (Paper 0478/12, June 2025). "Most candidates identified that a digital camera is an example of an input device. The most common incorrect answer given was storage device." Classify a device by its function in the scenario (capturing new data = input), not by whether it also happens to store data internally.

Output devices

⚙️
Actuator
Converts electrical signals into physical movement (e.g. a solenoid moving a plunger to open a valve).
🖨️
Inkjet / Laser printer
Inkjet sprays liquid ink through nozzles (thermal bubble/piezoelectric) — good for small colour batches. Laser uses a charged drum + toner + fuser — best for high-volume printing.
🧊
3D printer
Builds objects layer by layer (additive manufacturing) — direct (inkjet-style, moves in x/y/z) or binder (powder + glue) methods.
📺
LED / LCD / OLED screen
LED screens are made of tiny diodes. LCD screens need backlighting (often LED-backlit — not the same as a true LED screen). OLED emits its own light, no backlight needed.
📽️
DLP / LCD projector
DLP uses millions of tilting micro-mirrors (higher contrast, quieter). LCD splits light through 3 colour panels then recombines it (sharper image, better colour saturation).
🔊
Speaker
A DAC converts digital data to an analogue current, which is amplified; current in a coil vibrates a cone against a magnet to produce sound.
📌 Common trap: many TV screens marketed as "LED" are actually LCD screens that are merely LED-backlit, not true LED screens where each pixel is its own diode. Real examiner evidence (Paper 0478/12, June 2025): "Most candidates were able to give an appropriate printer" — device identification is usually well answered; the marks that separate top answers come from justifying the choice against the scenario's exact requirements (batch size, quality, cost).
Inkjet printerLaser printer
MediumLiquid ink cartridgesDry powdered toner (static electricity)
Best forOne-off photos, small batches of colourHigh-volume, high-quality printing
Common step (both)Document → printer driver → printer buffer; if the buffer empties before the document ends, the printer sends an interrupt to the CPU requesting more data.

Sensors

Sensors are input devices that read/measure physical properties from their surroundings. Real-world data is analogue (constantly changing); a computer needs an analogue-to-digital converter (ADC) to process it, and a digital-to-analogue converter (DAC) to drive an actuator in response. Sensors send out constant values — it's the microprocessor that decides what action to take.

SensorWhat it measuresExample application
TemperatureTemperature of surroundingsCentral heating control
MoistureWater level (electrical resistance)Soil moisture in a greenhouse
HumidityWater vapour in air (air conductivity)Humidity in a microchip factory
LightBrightness (photoelectric cells)Automatic street lights
Infra-red (active)A broken beam changes the readingRain-sensing windscreen wipers
Infra-red (passive)Heat radiation given off an objectSecurity alarm detecting body heat
PressureApplied pressure (transducer)Weighing lorries at a weigh station
AccelerometerAcceleration/motion (piezoelectric cell)Deploying airbags in a crash
ProximityPresence of a nearby objectSwitching off a phone screen during a call
💡 "Select the most suitable sensor" rule. First identify the exact physical quantity named in the scenario (e.g. "detect an intruder's body heat" → passive infra-red, NOT active infra-red). Similar-sounding sensors (moisture vs humidity; active vs passive infra-red) measure genuinely different things — match the precise definition, not just the general topic.
🧮 Worked example — central heating control system (monitoring vs control)
1The required (pre-set) temperature is stored in the microprocessor's memory.
2A temperature sensor constantly sends readings via an ADC to the microprocessor.
3The microprocessor compares the reading with the pre-set value.
4If reading < pre-set: a signal is sent via a DAC to an actuator, opening the gas valve and starting the pump.
➜ This is a control system (output affects the next input = a feedback loop) — a monitoring system would only raise an alarm, with no effect on what's being monitored.

3.3 Data Storage

Primary memory (RAM/ROM), secondary and off-line storage, magnetic/optical/solid-state technology, virtual memory and cloud storage

Primary memory — RAM and ROM

Primary memory is directly accessible by the CPU: RAM and ROM.

FeatureRAMROM
PersistenceTemporaryPermanent
VolatilityVolatile — lost on power-offNon-volatile
Writable?Can be written to and read fromCannot be altered — read only
Typical useData, files, programs, part of the OS in useBIOS/start-up instructions (bootstrap)
Effect of increasing sizeCan improve computer speedNo effect on performance
📌 DRAM vs SRAM. Dynamic RAM (DRAM) uses transistors + capacitors, must be refreshed roughly every 15 microseconds, is cheaper/higher capacity — used for main memory. Static RAM (SRAM) uses flip-flops, needs no refresh, is much faster (~25 ns vs ~60 ns) — used for CPU cache.
⚠️ Real examiner evidence (Paper 0478/12, June 2025, Q1a). When RAM is already given in the question, "another example of primary storage" must be something else — ROM, cache or a register are all valid; repeating RAM earns no marks. For "why is data only temporary in RAM", the precise mark-scheme phrase is "it is volatile — data is lost when the power is turned off," not a vaguer "it just holds things for a while."

Secondary and off-line storage

Secondary storage is not directly addressable by the CPU, unlike RAM/ROM. It is always non-volatile, holds far more data than primary memory, but has much longer access times. It stores the OS, applications, device drivers and general files, and can be internal (HDD/SSD) or external/off-line (DVD, Blu-ray, USB memory stick, removable HDD).

💡 Why secondary storage is needed: RAM is volatile and limited in size, so a non-volatile store is needed to hold the OS, applications and files permanently, even when the computer is off. A full-mark answer justifying a device as "secondary storage" should give both defining features together — not directly addressable by the CPU, and non-volatile/permanent — since real mark schemes reward each as a separate point.

Magnetic, optical and solid-state storage

📌 SSD benefits: no moving parts, more reliable, lighter, faster, cooler, no spin-up delay. SSD drawback: limited write endurance (commonly rated ~20 GB/day over 3 years) — this is why SSDs aren't yet used in every very-high-write-volume server.

Virtual memory

If running processes exceed available RAM, the system could crash. Virtual memory solves this using the HDD/SSD as extra memory: RAM is the physical memory, while virtual memory is RAM + swap space on the HDD/SSD. Data is moved between RAM and disk in pages (fixed-length blocks) using paging, giving the illusion of more memory than physically exists.

⚠️ Real examiner evidence (Paper 0478/11, June 2025, Q7c). "The most common mark awarded was for stating that secondary storage is partitioned to create the virtual memory" — but this earns only the first, most basic mark. A full-mark answer must continue: data/pages are actively swapped between RAM and this partition (oldest data moved out first) as programs compete for RAM, giving the illusion of unlimited memory.
💡 Disk thrashing: if too much time is spent swapping data rather than processing it, speed drops badly — the extreme case, where execution halts entirely, is the thrash point. Reduce thrashing by: installing more RAM, running fewer programs, reducing swap file size, or using an SSD instead of an HDD.

Cloud storage

Cloud storage stores data on remote servers rather than a local device, often duplicated across servers (data redundancy) for reliability. Types: public (client and provider are different companies), private (client and provider operate as one entity, behind a company firewall), hybrid (a mix of both).

BenefitsDrawbacks
Access from any device, anywhere, anytimeSlow/unstable internet makes access difficult
Remote back-up helps disaster recoveryProvider could fail — risking loss of backup data
Recovery still possible if own HDD failsCompany gives up direct control of its own data security
⚠️ Command word discipline. Cloud storage still requires real, physical servers owned by the hosting company — never describe it as "storage with no physical hardware." A full-mark "disadvantage" answer should reflect that a client has handed over physical control of their data to someone else's infrastructure.

3.4 Networking Hardware

NIC, MAC addresses, IP addresses and routers — the hardware that connects a computer to a network

Network interface card (NIC)

A device needs a network interface card (NIC) to connect to a network such as the internet. It is usually part of the device's hardware and contains the MAC address, generated at manufacture. A wireless NIC (WNIC) does the same job over an antenna, using microwaves, and typically plugs into USB or is built in.

📌 Do not confuse the NIC (the physical hardware component) with the addresses/protocols it enables (MAC address, IP address) — those are separate concepts, covered next.

Media Access Control (MAC) address

A MAC address is 48 bits, shown as six groups of hex digits: the first three groups are the manufacturer's code, the last three are the device serial number. It is set at manufacture (a Universally Administered Address, UAA) — the most common type — though it can be user/organisation-changed (a Locally Administered Address, LAA), e.g. to bypass a MAC filter.

🧮 Worked example — reading a MAC address
1MAC address: 00-1C-B3-4F-25-FF.
2First six hex digits (00-1C-B3) identify the manufacturer.
3Second six hex digits (4F-25-FF) are the unique device serial number.
➜ If the NIC is replaced, the MAC address changes too — the address belongs to the hardware, not the device as a whole.
💡 MAC vs IP rule. MAC = "who/what, physically" (identifies the physical device, assigned once by the manufacturer). IP = "where, on the network" (identifies a device's location on the internet; can be static or dynamic). Never conflate the two.

🧮 Worked example — how a device finds a website
1A device with a dynamic IP requests internet access; a DHCP server assigns a temporary IP address.
2The required URL is sent to a Domain Name Server (DNS), which looks up its database for the matching IP address and returns it.
3The device sends a request to the website server's IP address; the server sends the webpage back.
➜ A static IP address skips step 1 (no DHCP request needed) since the address never changes.
⚠️ Real examiner evidence (Papers 0478/12 & 0478/13, June 2025). "Few candidates were able to describe the role of the DNS. The most common correct answer given was for stating the DNS converts a URL into an IP address" — but the fuller, higher-mark description is that the DNS searches/looks up a database for the IP address matching the domain name/URL, not just "it converts" it.

Routers

A router enables data packets to be routed between different networks (e.g. joining a LAN to a WAN/the internet). It converts data from one network's protocol/format to another's, so the two can communicate. Inside a LAN, a switch passes data to the correct device using its MAC address; the router passes data between the LAN and the wider internet using IP addresses, and can assign private IP addresses to devices on the LAN.

💡 Three-part router definition rule. A full-mark "describe the role of a router" answer covers all three points together: (1) routes/sends data to a specific destination between networks; (2) can assign IP addresses to devices on its network; (3) connects a local network (LAN) to the internet (WAN). Naming only one loses marks, since real 0478 mark schemes for multi-point definitions award one mark per distinct point up to a maximum.

🔑 Key terms

CPU / Microprocessor
Executes/processes all instructions and data; a microprocessor is a CPU on one chip.
Von Neumann architecture
The stored-program concept: CPU accesses memory directly, programs stored with data.
Register (PC/MAR/MDR/CIR/ACC)
Small, fast storage locations inside the CPU used during the FDE cycle.
Cache
Fast memory inside the CPU storing frequently used instructions/data.
Instruction set
The complete list of opcodes a CPU can process, in machine code.
Embedded system
Hardware + software built for one dedicated set of functions.
Sensor / ADC / DAC
Reads a physical property / converts analogue↔digital.
RAM / ROM
Volatile, writable working memory / non-volatile, read-only start-up memory.
Secondary storage
Non-volatile, not directly CPU-addressable; permanent storage (HDD/SSD/optical).
Virtual memory
RAM + swap space on disk; pages swapped to avoid running out of RAM.
Cloud storage
Data stored on remote servers, often duplicated (data redundancy).
NIC
Hardware needed to connect a device to a network; holds the MAC address.
MAC address
48-bit hardware address: manufacturer code + device serial number.
IP address
Identifies a device's location on the internet; static or dynamic.
Router
Routes data between networks, assigns IP addresses, links LAN to internet.

📌 Exam tips

Never confuse a CPU component with a measurement of it — "clock" is a component, "clock speed" is not. This exact mix-up cost real candidates marks in June 2025.

For embedded systems, always give a second, independent point beyond "dedicated function vs many functions" — e.g. hardware type, ease of reprogramming, or standalone vs built-in.

For multi-point definitions (router, "why X is needed"), list every distinct point the mark scheme could be looking for — one mark is usually awarded per independent point, up to a maximum.
